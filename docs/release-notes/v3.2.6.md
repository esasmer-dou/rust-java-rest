# v3.2.6

This release keeps the native ABI unchanged and adds a small application bootstrap API for services
that want less repeated startup code without hidden auto-configuration.

## What Changed For Users

- `RestApplication` is now available for application startup.
- Repeated HTTP startup, runtime profile application, route scanning, native server start, and
  shutdown-hook wiring can move to the framework.
- Handler registration remains explicit. The framework does not export every class on the classpath
  and does not change the Java business-code model.
- Existing manual startup with `NativeBridge.startHttpServer(...)` still works.
- The recommended companion versions are now `java-rust-cache:0.2.2` and `java-rust-dubbo:0.2.1`.

## Example

```java
public final class OrdersApplication {
    public static void main(String[] args) {
        RestApplication.builder()
                .scan("com.example.orders")
                .handlers(HealthHandler.class, OrderHandler.class)
                .shutdownThreadName("orders-shutdown")
                .start();
    }
}
```

For small explicit applications:

```java
public final class CatalogApplication {
    public static void main(String[] args) {
        CatalogClient client = CatalogClient.open();
        RestApplication.builder()
                .handlerInstances(new HealthHandler(), new CatalogHandler(client))
                .closeable(client)
                .disableRouteIndexValidationIfNotExplicit(true)
                .start();
    }
}
```

## Recommended Version Set

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.2.6</version>
</dependency>

```

## Compatibility Notes

- No native DLL/SO rebuild is required for this release.
- Existing REST annotations, response types, and handler code remain source-compatible.
- `RestApplication` is additive. It is a convenience API, not a required migration.

## Validation Gate

Before promoting this version in a service, run at least:

- Maven test/install for `rust-java-rest`.
- Maven test for the consuming application.
- A startup smoke that confirms the intended handler list is active.
- If Dubbo or Redis companion libraries are used, use the aligned versions above.
