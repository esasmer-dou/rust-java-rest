# v3.1.0-rc2 - UTF-8 Response Contract Patch

This release candidate keeps the v3.1.0 Rust I/O plane direction and fixes a production response
encoding issue reported during pilot usage: Turkish characters and other non-ASCII text should no
longer depend on client-side default decoding.

The programming model is unchanged. Controllers, handlers, services, components, and business logic
remain Java-side. This release updates the response contract, native fallback behavior, packaged native
libraries, and release documentation.

## What's New For Users

- JSON responses now explicitly return `Content-Type: application/json; charset=utf-8`.
- Text responses now explicitly return `text/plain; charset=utf-8` when created through `RawResponse.text(...)`.
- `RawResponse.json(...)`, `RawResponse.registeredJson(...)`, and `RawResponse.nativeJson(...)` now keep UTF-8 JSON metadata.
- Existing `@ContentType` annotations are now honored by the handler registry.
- Turkish characters such as `İstanbul şeker ölçü` are covered by regression tests at response-frame level.
- The bundled Windows and Linux native libraries were rebuilt and included in the package.

## Changelog

- Added response content-type normalization for textual media types: `text/*`, `application/json`, and `*+json`.
- Added default JSON UTF-8 header injection for normal `ResponseEntity`, auto-serialized DTO, custom-status, and async-error paths.
- Preserved `FileResponse` and `RawResponse` behavior without adding duplicate default JSON headers.
- Added Rust-side content-type normalization for Java frame, raw body, zero-copy, file response, and registered static response paths.
- Replaced selected platform-default `String.getBytes()` usage with `StandardCharsets.UTF_8`.
- Updated Maven metadata to pin `java-rust-dubbo` to its independent `0.1.0-rc1` version instead of coupling it to the framework version.
- Removed the package-time dependency on the local `dubbo-sample-api` artifact by keeping the minimal example contract in the framework module.
- Updated package version to `3.1.0-rc2`.


## Production Note

This release is a correctness patch over the v3.1.0 RC line. It should be preferred over `v3.1.0-rc1`
for pilot applications that return Turkish or other non-ASCII response content.
