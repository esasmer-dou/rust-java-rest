# Rust-Java REST 4.7.1

[English](v4.7.1.md) | [Türkçe](v4.7.1.tr.md)

## What Changes For Your Application

Java handlers, services and annotations stay the same. Upgrade your platform parent/BOM and REST dependencies together to `4.7.1`. Use the native files inside that version; do not copy an older DLL or SO.

When telemetry is disabled, no exporter is started. When micro telemetry is enabled with trace capacity zero, requests still contribute to exact route counts, errors and latency aggregates. They no longer run the unused trace sampler. The completion path passes scalar nanoseconds directly to Rust counters. Diagnostic traces remain available when their bounded queue is enabled.

No heap, worker, connection, queue or JVM defaults are increased. Export stays on the isolated Rust exporter, not the Hyper request executor. These changes do not cache HTTP response bodies.

## Native Compatibility

Clean source: `ccf11143cea8b7513706c439c67939b7803469d0`. REST ABI `29`, Dubbo `7`, Redis `6`, Glowroot `6` are unchanged. Windows x64, Linux x64/ARM64 and macOS ARM64 are packaged together. Linux retains the GLIBC `2.17` floor.

Cancelling the exporter before its first execution now releases native ownership. A quick close and
restart no longer leaves a stale claim. The cache starter aligns to `java-rust-cache:0.8.1`, so a
standalone cache process also receives the corrected runtime. Redis APIs and defaults do not change.

## Qualification

Publication is conditional on the matching agent 0.7.0 production gate: micro off/on, small and raw JSON, c64/c256, at least three valid pairs. Limits remain 3 MiB paired-median RSS/container delta, at most 2% useful-RPS loss and 10% p99 increase, with error/startup/thread checks. This is not a claim that every individual RSS peak is below 3 MiB.
