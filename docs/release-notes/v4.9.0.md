# 4.9.0: Uploads, WebSocket And Packaged Assets

[English](v4.9.0.md) | [Turkish](v4.9.0.tr.md)

## Upgrade

Set `com.reactor:rust-java-rest` and the REST platform parent/BOM to `4.9.0`.
Use the native library from this package. If you use `-Drust.lib.path`, replace
the explicit DLL/SO/dylib as part of the upgrade. JNI remains the default;
REST 29, Dubbo 7, Spring Dubbo 3, Redis 6 and Glowroot 6 are unchanged.

## Pick The Right Path

| Use case | What to do |
| --- | --- |
| Upload a form and receive a `MultipartFile` | Keep your handler. Native boundary scanning reuses the existing upload contract and limits; it does not turn the upload into a stream. |
| Echo or drop a binary WebSocket message | Implement `WebSocketBinaryForwarder` on the endpoint. Return `true` to send the original bytes back on the same session. |
| Transform, inspect or broadcast a binary message | Keep the `@OnMessage` callback with `byte[]`. The forwarder replaces that callback, not the text or lifecycle callbacks. |
| Serve static, versioned files from your JAR | Generate asset fixtures at build time. Declare an exact GET route with `@NativeStaticFileRoute`. Rust serves identity or gzip with variant ETags. |
| Serve authorized, generated or partial content | Use the existing application response or file route instead. Packaged assets bypass Java request processing and do not support byte ranges. |

## WebSocket Example

```java
import com.reactor.rust.websocket.WebSocketBinaryForwarder;
import com.reactor.rust.websocket.WebSocketSession;
import com.reactor.rust.websocket.annotation.WebSocket;

@WebSocket("/ws/echo")
public final class BinaryEcho implements WebSocketBinaryForwarder {
    public boolean shouldForwardBinary(WebSocketSession session, int length) {
        return length <= 64 * 1024;
    }
}
```

Register the endpoint as a bean and enable WebSocket with
`reactor.websocket.enabled=true`. Keep the decision non-blocking.

## Packaged Asset Example

Run `com.reactor.rust.http.PackagedAsset target/classes/assets/app.js application/javascript`
with the REST dependency on the Java classpath before creating the application
JAR. Keep the original file and the generated sidecar files together.

```java
@GetMapping(value = "/assets/app.js", responseType = FileResponse.class)
@NativeStaticFileRoute
public FileResponse script() {
    return FileResponse.packagedAsset(getClass(), "/assets/app.js")
            .header("Cache-Control", "public, max-age=600");
}
```

The release covers these paths only. It does not claim that all experimental
RD optimizations passed performance acceptance or that every workload gains.
