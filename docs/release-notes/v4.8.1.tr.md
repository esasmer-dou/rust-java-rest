# 4.8.1 — ARM64 Paket Düzeltmesi

[English](v4.8.1.md) | [Türkçe](v4.8.1.tr.md)

2026-10-30 tarihli kararlı düzeltme sürümüdür. 4.8.0'dan geçiş adımları aşağıdadır.

## Kim Güncellemeli?

Linux ARM64 veya macOS ARM64 kullanan uygulamalar bu düzeltmeye geçmelidir.
4.8.0 JAR'ındaki ARM dosyaları günceldir; yanlarındaki platform
manifestleri eskidir. Yükleyici bu uyuşmazlığı native dosya yüklenmeden reddeder.

REST ve platform için birlikte `4.8.1` kullanın. Cache kullanıyorsanız `0.9.1`
sürümüne hizalayın. Sample servisler `0.8.1`, model `0.5.1`, utility `0.5.1` kullanır.
Dubbo `0.9.1`, REST bağımlılığını hizalar. Spring Dubbo `0.8.1`, consumer metodu
ve referansı için zaman aşımı desteği ekler. Agent `0.7.1` olarak kalır.

## Ne Değişiyor?

- ARM platform manifestleri, paketlenen dosyalar ve ortak kaynak sürümü
  `3418671b5010afb5dc049897f2a7287dc6a58daf` üzerinden yeniden üretilir.
- JAR içindeki her native dosyanın özeti, yükleyicinin seçtiği manifestle
  karşılaştırılır. Hatalı platform manifesti paket kontrolünü başarısız yapar.
- ARM doğrulama sınırı korunur: `current-source-compile-verified` ve
  `runtime.verified=false`. Linux ARM64 hedefi GLIBC 2.17'dir.

Native dosyalar yeniden derlenmez veya değiştirilmez. Java API'si ve ABI'ler
değişmez. Windows x64 ve Linux x64 dosyaları aynıdır. Sözleşmeler REST 29, Dubbo 7,
Spring Dubbo 3, Redis 6 ve Glowroot 6 olarak kalır.

## Nasıl Geçilir?

Platform parent/BOM veya REST bağımlılığını `4.8.1` yapın. Cache kullanıyorsanız
onu `0.9.1` yapın. Uygulamayı yeniden derleyin. Bu JAR'ların native kaynaklarını
birlikte kullanın. Yalnız manifesti değiştirmeyin; başka sürümden native dosya
kopyalamayın. İsteğe bağlı özelliklerin varsayılanları korunur. Bu paket
düzeltmesi yeni RPS, p99 veya RSS kazanımı ya da ARM çalışma testi iddiası taşımaz.
