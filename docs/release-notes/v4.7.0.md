# Rust-Java REST 4.7.0

Java handlers and business logic stay in Java. Existing REST annotations remain unchanged.

## What You Can Use

- Add `com.reactor:rust-java-jdbc:4.7.0` only in database processes. Use explicit transactions, bounded cursors, opt-in PostgreSQL idempotency and refresh notifications. The module has no runtime third-party dependency.
- Use `ErrorResponses.from(error)` for consistent sync/async error handling. Successful response bodies do not change.
- Generate a runnable cache reader/writer or Dubbo consumer/provider pair with `ScenarioGenerator` from the matching codegen JAR.
- Inspect explicitly allowed effective settings and validate configuration at startup. No runtime classpath scan or polling thread is added.
- Compare generated contract manifests during the build with `reactor:verify-contract`.

## Runtime Compatibility

Primitive JNI callbacks now use the correct long/boolean/double/short descriptors. Invalid callback results return a real HTTP 500 and the worker can recover. Async response ownership and connection cancellation cleanup are bounded. Common JSON headers avoid rebuilding the same string; response bodies are not cached.

Use the DLL/SO packaged with this release. Native source: `a5ff8d2a1c06a3ca197b6b71b43c4909daadfe73`. REST ABI 29, Dubbo ABI 7, Redis ABI 6 and Glowroot ABI 6 remain unchanged. Linux x64/ARM64 retain the GLIBC 2.17 floor; Windows x64 and macOS ARM64 are included.

## Upgrade

Select platform parent/BOM 4.7.0, java-rust-cache 0.8.0 and java-rust-dubbo 0.8.0 together. No new JVM flag or larger worker/queue/heap default is required. Extra DB work occurs only where explicitly enabled; there is no hidden write retry.

## Measured Scope and Accepted Deviations

The stable publication accepts the specific deviations below. The original full comparison is **not** a strict no-regression PASS, and its thresholds remain unchanged.

| Measurement | Before | After |
| --- | ---: | ---: |
| Cache c16 / c64 useful RPS | 9,231 / 9,012 | 9,276 / 9,197 |
| Cache c16 / c64 mean trial p99 (ms) | 10.541 / 17.611 | 10.240 / 16.759 |
| Writer mean peak RSS (MiB) | 92.417 | 91.382 |
| Writer mean job p99 (ms) | 2.536 | 2.450 |
| Writer final-idle RSS (MiB) | 77.268 | 78.591 |
| Consumer mean / worst peak RSS (MiB) | 82.565 / 86.207 | 82.648 / 85.379 |
| Consumer DB c64 useful RPS | 9,769 | 9,592 |
| Consumer DB c64 mean trial p99 (ms) | 8.870 | 9.625 |

Consumer DB c64 is -1.814% RPS and +8.52% p99. All six consumer cohorts meet the existing 0.98 RPS / 1.10 p99 band, but four fail the strict zero-regression flag. Mean consumer peak RSS rises by 0.083 MiB; writer idle RSS rises by 1.323 MiB. These are accepted release risks, not proven leaks or proven measurement noise.

Three fresh pairs per workload used matched Linux images, Java business work, 1 CPU and 128 MiB. The baseline is the frozen phase2 image, not a fresh installation of the previous published version. Cache and consumer completed 10,457,701 measured requests without HTTP, socket or body-validation errors. The writer uses a fixed schedule; its results do not measure maximum RPS.

[Original three-lane run](https://github.com/esasmer-dou/rust-java-rest/actions/runs/39224021675) failed: writer CPU/p99 and consumer reporting. Consumer reporting was recovered from unchanged raw metrics by restoring missing cohort metadata. The [writer-only reconfirmation](https://github.com/esasmer-dou/rust-java-rest/actions/runs/39226090814) passed after equal warmup was increased from 200 to 400 publications. It does not turn the original run into a PASS. JIT activity remained nonzero. This release does not claim a new topology-failover or long-soak qualification.
