# rust-java-rest v3.4.0

`v3.4.0` reduces native and Java-side memory retained after traffic bursts while keeping Java
handlers, annotations, services, records, and response APIs compatible.

## What's New

- Replaced thread-local async response frames with a bounded process-wide pool.
- Added `reactor.rust.async.frame-initial-bytes`, pool-capacity, and retain-cap controls.
- Allowed native response-pool buckets to use capacity `0`, which disables retention for that size
  class without disabling responses.
- Tightened the `micro-rest` response pool to `8/2/0/0` for small/medium/large/huge buckets.
- Shrink oversized request maps after bursts and keep path/query map ownership separate.
- Reduced async completion-stage allocation and release the async permit before response encoding.
- Added async frame pool metrics to the framework metrics and memory diagnostics endpoints.
- Added repeatable Linux smaps and paired-image benchmark tools.

## Aligned Runtime Line

Use these versions together when the same process uses REST, Dubbo, or Redis native paths:

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.4.0</version>
</dependency>
```

- `java-rust-dubbo:0.4.0`
- `java-rust-cache:0.4.0`
- REST ABI `24`, Dubbo ABI `6`, Redis ABI `6`

## Measured Memory Gate

In the matched minimal-production OpenJ9 async-producer gate, final cgroup memory moved from
`53.00 MiB` to `46.93 MiB`, cgroup anon from `46.00 MiB` to `40.52 MiB`, c64 RPS increased from
`4,395` to `5,573`, and c64 p99 moved from `46.79 ms` to `41.09 ms`. These figures describe that
controlled endpoint and profile, not every application workload.

`MALLOC_ARENA_MAX=1` and reduced OpenJ9 compilation threads were tested and rejected as defaults
because they reduced throughput or increased memory. The production baseline remains explicit,
bounded, and measurement-driven.

## Compatibility

- Existing REST annotations and handler signatures are unchanged.
- Existing DTO serialization remains available.
- Pool capacity `0` changes retention only; it does not reject that response size.
- The packaged Windows DLL and Linux SO are required because the native ABI changed.
