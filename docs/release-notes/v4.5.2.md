# Rust-Java REST 4.5.2

`4.5.2` is a stable telemetry scheduling bugfix. Existing Java handlers, annotations, services,
DTOs, validation, and business logic do not change.

## What Changed

- Embedded REST telemetry validates collector reachability at startup and releases that probe.
- It opens one bounded h2 connection only for an export window. No idle collector connection shares
  the CPU budget used by Hyper request handling.
- The standalone Spring agent continues to reuse one bounded collector connection in its isolated
  Rust runtime.
- The exporter remains on one lower-priority `256 KiB` native thread.

## Compatibility

REST ABI remains `29`; Glowroot ABI remains `3`; Dubbo ABI remains `7`; Redis ABI remains `6`. Use
the Windows DLL or Linux SO packaged inside `com.reactor:rust-java-rest:4.5.2`. Do not copy a native
binary into a different Maven version because startup verifies source revision and SHA-256.
