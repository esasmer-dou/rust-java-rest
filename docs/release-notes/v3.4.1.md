# rust-java-rest v3.4.1

`v3.4.1` refreshes the packaged native runtime for the aligned Dubbo safety and provider-capacity
release. Java REST handlers, annotations, services, records, and response APIs remain unchanged.

## What Changed

- Packaged Windows x64 and Linux x64 native libraries now use REST ABI `24`, Dubbo ABI `7`, and
  Redis ABI `6`.
- Native Dubbo idle connections can expire and are validated before reuse, preventing a provider
  restart from leaving a stale pooled socket on the next request.
- Native provenance and SHA-256 checks identify the clean source revision used for both binaries.
- Release workflow validation now rejects a package that does not carry the `24/7/6` ABI line.

## Aligned Dependencies

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.4.1</version>
</dependency>
```

- `java-rust-dubbo:0.4.1`
- `java-rust-cache:0.4.1`

When REST and Dubbo share one process, upgrade both dependencies together. Do not copy a DLL or SO
from an older release into the image.

## Compatibility

- No REST annotation changed.
- No handler signature changed.
- Existing runtime profiles and properties remain valid.
- REST-only applications receive a native compatibility refresh; the new connection behavior is
  used only by native Dubbo clients.

## Validation

- Rust native test suite: `29` tests passed.
- Maven tests passed for the REST framework, Dubbo library, cache library, and both Dubbo samples.
- Windows DLL and Linux SO were rebuilt from the same clean source revision.
- Provider restart and idle-expiry gates completed without a native I/O error.
