# Rust-Java REST 4.5.0

`4.5.0` adds bounded, runtime-switchable Glowroot telemetry while preserving the existing Java REST
programming model.

## What Users Get

- Start with `reactor.glowroot.profile=micro` for the smallest telemetry surface.
- Temporarily switch to `jvm`, `sql`, `full`, or `diagnostic` during an incident.
- Return with `GlowrootTelemetry.restoreConfiguredProfile()`; profile-owned native memory and JNI
  references are released synchronously.
- Collect optional JVM memory/GC gauges, explicit SQL operation timings, bounded error stacks, and
  authorized thread/heap diagnostics without adding bytecode weaving, Java gRPC, or Netty.
- Keep telemetry work away from Hyper and application workers through one isolated `256 KiB` Rust
  thread.

## Minimal Configuration

```properties
reactor.glowroot.enabled=true
reactor.glowroot.profile=micro
reactor.glowroot.collector.address=http://glowroot-collector:8181
reactor.glowroot.agent.id=catalog::pod-1
reactor.glowroot.application.name=catalog-api
```

```java
GlowrootTelemetry.switchTo(TelemetryProfile.FULL, Duration.ofSeconds(5));
try {
    // Run the bounded incident inspection.
} finally {
    GlowrootTelemetry.restoreConfiguredProfile();
}
```

Do not expose profile switching or diagnostic commands through an unauthenticated public endpoint.

## Native Compatibility

| Contract | Value |
| --- | ---: |
| REST ABI | `29` |
| Dubbo ABI | `7` |
| Redis ABI | `6` |
| Glowroot ABI | `3` |

The packaged Windows DLL and Linux SO come from the same clean `rust-spring v4.5.0` commit. Their
SHA-256 values and exact 40-character source revision are recorded in the Maven provenance
manifest. Do not copy a DLL/SO from REST `4.4.x` or agent `0.2.x`.

Java annotations, handlers, services, validation, records, database access, RPC calls, and business
logic are source-compatible with `4.4.1`.
