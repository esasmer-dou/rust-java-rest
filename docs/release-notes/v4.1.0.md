# Rust-Java REST 4.1.0

`4.1.0` makes normal application setup shorter while keeping business logic in Java and HTTP I/O in
Rust Hyper.

## What You Use

```java
@ReactorApplication(scanBasePackages = "com.example.orders")
public final class OrderApplication {
    public static void main(String[] args) {
        RestApplication.run(OrderApplication.class, args);
    }
}

@RestController("/api/v1/orders")
final class OrderHandler {
    private final OrderService orders;

    OrderHandler(OrderService orders) {
        this.orders = orders;
    }

    @GetMapping("/{id}")
    OrderResponse order(@PathVariable("id") long id) {
        return orders.find(id);
    }
}
```

The build-only codegen artifact creates constructor factories and direct route invokers. Production
startup does not need annotation processor classes, and request handling does not gain runtime
reflection.

## What Is New

- Declarative application startup with `@ReactorApplication`.
- `@RestController` for constructor-injected route handlers.
- Generated constructor and `@Bean` parameter injection.
- Explicit `@Primary` and `@Qualifier` handling when more than one bean exposes an interface.
- Clear startup errors for ambiguous beans and checked factory failures.
- `LongKeyAdmission` for bounded per-key command execution.
- Project generator support for REST, cache reader/writer, static Dubbo, and ZooKeeper Dubbo shapes.
- Separate runtime and `codegen` JARs with artifact boundary verification.

## Aligned Versions

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>4.1.0</version>
</dependency>
```

Use `java-rust-dubbo:0.6.0` and `java-rust-cache:0.6.0` with this release.

## Compatibility

Java handlers, services, records, validation, response APIs, runtime profiles, and native ABI values
remain unchanged. The packaged Windows DLL and Linux SO still implement REST ABI `24`, Dubbo ABI
`7`, and Redis ABI `6`.

`RestApplication.Module` remains available for applications that intentionally ship different,
isolated runtime surfaces. Normal applications should use the declarative model above.
