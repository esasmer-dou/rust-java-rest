# Rust-Java REST 4.3.0

`4.3.0` improves startup, generated route execution, and resident memory without changing where
application code lives. Handlers, services, records, validation, database access, and business
rules stay in Java. Rust continues to own HTTP I/O, bounded native buffers, response transport, and
selected serialization-heavy paths.

## Upgrade

Use the aligned platform parent when possible:

```xml
<parent>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-platform-parent</artifactId>
  <version>4.3.0</version>
</parent>
```

The aligned release train is:

| Artifact | Version | Purpose |
| --- | ---: | --- |
| `rust-java-rest` | `4.3.0` | REST runtime, codegen, native HTTP transport |
| `java-rust-dubbo` | `0.7.1` | Native Dubbo consumer integration |
| `java-rust-cache` | `0.7.1` | Native Redis integration |
| `rust-sample-model` | `0.4.1` | Shared sample records |
| `rest-sample-utility` | `0.4.1` | Shared sample contracts |

Always use the DLL/SO packaged with this release. REST ABI remains `26`, but native implementation
and hashes changed.

## What Changes For Users

### Normal response records

Keep using `@Response` for ordinary JSON DTOs:

```java
@Response
record CatalogItem(long id, String name) {}
```

This uses the normal supported serializer path. It does not generate a direct writer implicitly.

### Hot response records

Use `@GenerateDirectJsonWriter` only after profiling identifies a hot JSON response:

```java
@Response
@GenerateDirectJsonWriter
record CatalogItem(long id, String name) {}
```

The writer is generated and bound during build/startup. Unsupported shapes fail the build instead
of silently falling back on every request. Route diagnostics show the selected strategy.

### Startup and image preparation

Generated component descriptors, route invokers, and native digest checks now retain less temporary
state. The Maven runtime-image path can prepare an OpenJ9 shared class cache without placing build
tools in the runtime image. Keep this image option service-local and validate it with the included
startup and resident-image gates.

## Performance Gate Result

The release gate compared the same application before and after the changes. Generated invocation
improved useful RPS by about `2.6-3.0%` at c64/c256 and reduced p99 by about `2.0-4.1%`. Echo and
small-direct stayed inside the no-regression gate. Internal framework ready time improved by about
`3.3%`, while measured memory deltas stayed within roughly `-0.47 MiB` to `+0.59 MiB` depending on
route and concurrency. These are release gates, not universal workload promises.

## Compatibility

- Existing Java handler and service code remains valid.
- Existing `@Response` DTOs remain valid.
- Existing explicit `@GenerateDirectJsonWriter` DTOs keep the generated path.
- No native ABI number changed.
- Do not reuse native binaries from `4.2.0`; package hashes are release-specific.

## Verification

The release passed Java tests, all `30` Rust tests, package-boundary verification, generated source
checks, isolated sample build, UTF-8 HTTP smoke checks, and resident/startup performance gates.
