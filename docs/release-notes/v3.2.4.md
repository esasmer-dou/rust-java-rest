# v3.2.4

This release keeps the normal Rust-Java REST programming model unchanged. Java still owns handlers,
services, records, validation, database calls, and business rules. The update is about native Redis
cache compatibility and safer production failover behavior for applications that use `java-rust-cache`.

## What Changed For Users

- The packaged native binaries now expose Redis native ABI version `3`.
- `java-rust-cache:0.2.1` can pass `reactor.cache.redis.sentinel.master-check-ms` into Rust so Sentinel
  mode can refresh the current master independently from the slower Cluster topology refresh interval.
- Cluster behavior remains compatible with ABI version `2`; Sentinel failover refresh now requires ABI
  version `3` and fails early if an older native binary is loaded.
- The same Windows and Linux native binaries are shipped as release assets and inside the Maven package.

## Recommended Version Pair

Use these versions together when an application combines REST and the Redis cache library:

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.2.4</version>
</dependency>

<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-cache</artifactId>
  <version>0.2.1</version>
</dependency>
```

For Sentinel, start with:

```properties
reactor.cache.redis.topology=sentinel
reactor.cache.redis.nodes=redis-sentinel-0:26379,redis-sentinel-1:26379,redis-sentinel-2:26379
reactor.cache.redis.sentinel.master-name=mymaster
reactor.cache.redis.sentinel.master-check-ms=1000
```

## Validation

This release line was validated with:

- Rust native unit tests.
- Maven test/install for `rust-java-rest`.
- Maven test/install for `java-rust-cache`.
- Sample cache reader and writer tests.
- Redis Sentinel live failover gate.
- Redis Cluster `MOVED`/`ASK` live redirect gate.
- Redis Cluster replica live failover gate.

For production, still run a short load/soak gate under your real Kubernetes CPU and memory limits,
especially if Sentinel recovery time or Redis Cluster resharding behavior is part of your availability
model.
