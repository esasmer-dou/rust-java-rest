# 4.8.2: Sınırlı Native Yanıtlar

[English](v4.8.2.md) | [Turkish](v4.8.2.tr.md)

## Uygulamanızda Ne Değişir?

Java handler, servis ve ayarlarınız aynı kalır. Platform parent veya REST
bağımlılığını `4.8.2` yapın. Ardından uygulamanızı yeniden derleyin. Cache veya
Dubbo kullanıyorsanız bu kütüphanelerin `0.9.2` sürümünü seçin.

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>4.8.2</version>
</dependency>
```

## Yanıt Hazırlarken Daha Az Nesne

Başlıklarına erişilmeyen bir `RawResponse.json(body)` artık değiştirilebilir
başlık haritası oluşturmaz. Başlık okuma ve değiştirme desteği korunur. Bu bir
yanıt cache'i değildir. Her isteğin gövdesi ve kodlanmış başlıkları kendisine aittir.

```java
return RawResponse.json(jsonBytes);
```

Gövdesiz JNI handler'larında worker başına sınırlı bir yanıt boyutu tahmini
yeniden kullanılır. Başlangıç tahmini en fazla 16 KiB olur. Kuyruktaki istek
tamponları büyütülmez. İş verisi saklanmaz. Yanıt boyutu sınırları değişmez.

## Dubbo Tamamlama Kuyruğu

Ortak Rust runtime, sonucu kuyruktan alınca kuyruk iznini bırakır. Yanıt belleği
izni ise Java callback tamamlanana kadar korunur. Böylece önceki sonuç artık
kuyrukta değilken onun kuyruk izni yeni RPC çağrısını engellemez. Bellek sınırları
ve kapasite dolduğunda uygulanan kontrollü ret davranışı devam eder.

## Native Dosyaları Birlikte Güncelleyin

JNI sözleşmeleri değişmedi: REST 29, Dubbo 7, Spring Dubbo 3, Redis 6, Glowroot 6.
Bu sürümün paketindeki native dosyayı kullanın. Native dosya yolunu elle
veriyorsanız DLL/SO/dylib dosyasını da değiştirin. Yalnız Java bağımlılığını
güncellemek yeterli değildir. Temiz native kaynak revizyonu:
`26ee9b9f518077af1fc0817c8f37a96fd1a78533`.

## Doğrulamanın Kapsamı

EmaTech cache detail/segment c16/c64 karşılaştırmasında her taraf için üç yeni
JVM çalıştırıldı. RPS değişimi +%0,03 ile +%6,55 arasındaydı. p99 değişimi -%9,97
ile +%8,27 arasındaydı. Tepe RSS medyanı 79,66 MiB'den 79,41 MiB'ye indi.
Beklenmeyen istek hatası veya OOM görülmedi. Bu sonuçlar ölçülen iş yüküne aittir.
Her servis için aynı hız veya bellek sonucu vaat etmez.

REST test takımında 586 test çalıştı. 585 test geçti. OpenJ9 sayaç sağlamadığı
için bir allocation testi atlandı. Aynı test EmaTech HotSpot 21 üzerinde ayrıca
geçti: 100.000 işlemde 336 bayt ölçüldü. Sınır 8.192 bayttır. Bu ölçüm native
belleği kapsamaz ve OpenJ9 için sıfır allocation kanıtı değildir.

Uyumluluk ve uzun süreli çalışma kayıtları release eklerinde tutulur. Derleme,
platformda çalıştırma ve performans doğrulaması ayrı değerlendirilir. Bu patch
bellek, gecikme veya platform varsayılanlarını büyütmez.

EmaTech üzerinde 30 dakikalık testte 24 yük penceresi ve 17.430.899 istek
tamamlandı. İstek hatası, OOM veya yeniden başlama olmadı. Tepe RSS 68,36 MiB,
örneklenen tepe cgroup belleği 109,64 MiB oldu. Container sınırı 128 MiB idi.
Son iki boşta bekleme aralığındaki bellek yaklaşık sabit kaldı. Bu sonuç
30 dakikalık gözlemdir; günler süren kullanımda sızıntı olmayacağını garanti
etmez. Yayımlanan patch JAR'ları sınıf ve kaynak hash'leriyle ayrıca eşleştirilir.
