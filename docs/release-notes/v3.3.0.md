# rust-java-rest v3.3.0

`v3.3.0` makes application startup more declarative and keeps production artifacts focused on the
framework runtime. Existing REST annotations and Java business handlers remain supported.

## What's New

- Added `RestApplication.Module` and `ModuleContext` for declaring handlers and owned resources in
  one startup block.
- Managed resources now close in reverse order during normal shutdown and startup failure.
- Added `standardRuntimeFeatures()` for the standard profile, prewarm, footprint gate and idle
  native-memory policy.
- Added `JsonResponses` and improved generated DSL-JSON converter discovery.
- Moved sample and benchmark classes out of the core runtime JAR. The runnable examples are now in
  the separate `rust-java-rest-sample` artifact.
- Hardened route invocation, primitive request binding, error mapping, WebSocket lifecycle and
  native response handling.
- Added native provenance verification. Release binaries are built from native source commit
  `2a9929cac331`.

## Declarative Startup

```java
RestApplication.builder()
    .module(context -> {
        CustomerRepository repository = context.manage(CustomerRepository.open());
        context.handlers(new CustomerHandler(repository));
    })
    .standardRuntimeFeatures()
    .start();
```

Use `context.manage(...)` only for resources owned by the application. They are closed
automatically when startup fails or the JVM shuts down.

## Artifact Choice

Use the core dependency in production:

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.3.0</version>
</dependency>
```

Use `rust-java-rest-sample` only to run or inspect the examples. Sample classes are intentionally
not present in the production core JAR.

## Compatibility

- REST annotations and existing handler signatures remain compatible.
- The native REST ABI is now `23`; use the DLL/SO shipped with this version.
- Dubbo and Redis native ABI levels embedded in the shared runtime are both `5`.
- Applications that imported `com.reactor.rust.example.*` must use the separate sample artifact.
