# Rust-Java REST 4.6.0

[English](v4.6.0.md) | [Turkish](v4.6.0.tr.md)

`4.6.0` makes bounded HTTP telemetry visible in the existing Glowroot transaction screens without
changing Java handlers or REST annotations.

## What Users Get

- **Average, Percentile, Throughput, and Errors use exact request totals.** Successful requests are
  no longer removed by the trace sample rate.
- **Transactions use the expected Glowroot shape.** Select transaction type `Web`; `/orders/{id}`
  appears as `/orders/*`.
- **Trace cost stays bounded.** `reactor.glowroot.http.sample-rate` controls only optional trace
  detail. Keep `reactor.glowroot.trace.capacity=0` when aggregate dashboards are sufficient.
- **Cardinality remains bounded.** Excess route names are visible under
  `<route-limit-exceeded>` instead of disappearing.

## Maven

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>4.6.0</version>
</dependency>
```

Use the DLL/SO packaged by this dependency. The release uses REST ABI `29` and Glowroot ABI `4`.
An ABI `3` native file is intentionally rejected during startup.

If the same application uses the cache library, select `java-rust-cache:0.7.6`. The platform BOM
and cache starters already use this coordinated package. It carries the same ABI `4` native
revision.

## Verification

1. Start the application with bounded Glowroot telemetry enabled.
2. Send requests to at least two mapped routes.
3. Wait for one export interval; the default is 60 seconds.
4. Open Glowroot **Transactions** and select **Web**.
5. Confirm that route names and request totals match the traffic sent.

Windows and Linux native files were built from clean `rust-spring v4.6.0` source revision
`0ec9c9df091f225d3e78e6ced4f9b118dd9ba73c`. The Linux artifact is limited to GLIBC `2.17` symbols.
