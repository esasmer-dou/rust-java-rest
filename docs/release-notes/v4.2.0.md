# Rust-Java REST 4.2.0

`4.2.0` provides a more complete declarative framework experience while preserving the architecture:
Rust Hyper owns HTTP I/O and bounded native transport; handlers, services, validation, SQL, and
business decisions remain Java code.

## Start A Service

```xml
<parent>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-platform-parent</artifactId>
  <version>4.2.0</version>
  <relativePath/>
</parent>

<dependencies>
  <dependency>
    <groupId>com.reactor</groupId>
    <artifactId>rust-java-starter-rest</artifactId>
  </dependency>
</dependencies>
```

```java
@ReactorApplication(scanBasePackages = "com.example.orders")
public final class OrderApplication {
    public static void main(String[] args) {
        Reactor.run(OrderApplication.class, args);
    }
}
```

The parent manages aligned dependency and codegen versions. Add only the starter required by the
service. Cache, Dubbo, WebSocket, tracing, scheduler, security, and OpenAPI surfaces are not runtime
defaults.

## What Is New

- Platform parent and BOM with focused REST, WebSocket, OpenAPI, security, tracing, scheduler, HTTP
  client, Dubbo, cache reader/writer, and test starters.
- Build-time generated DI, route invocation, primitive binding, configuration binding, validation,
  exception handling, and application descriptors.
- `HttpResponse<T>` and `ProblemDetail` for explicit status, headers, and typed errors.
- Generated HTTP client and application feature extension points without request-time reflection.
- Immutable native route lookup after startup.
- A separate compatibility module for applications that intentionally need classpath scanning.
- A project generator that emits a bilingual README and the smallest dependency set for each shape.

## Upgrade Notes

1. Upgrade the platform parent or direct REST dependency to `4.2.0`.
2. Upgrade native Dubbo/cache libraries to `0.7.0` when used in the same service.
3. Remove handwritten annotation processor paths when the platform parent is used.
4. Select the smallest starter set; do not add every starter preemptively.
5. Deploy the DLL/SO packaged by this release. REST ABI `24` binaries are rejected at startup.

No Java business API was moved into Rust. Existing handler annotations and service classes remain
valid. `RestApplication.Module` remains available for intentionally isolated or advanced runtime
surfaces.
