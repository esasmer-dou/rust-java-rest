# v3.2.3

This release keeps the normal Rust-Java REST programming model unchanged: Java still owns handlers,
services, records, validation, database calls, and business rules. The update is mainly about native
runtime compatibility and Redis cache integration safety.

## What Changed For Users

- `rust-java-rest` now carries the Redis native ABI version required by `java-rust-cache:0.2.0`.
- Applications using `java-rust-cache` with Redis Sentinel or Redis Cluster should align versions:
  use `rust-java-rest:3.2.3` with `java-rust-cache:0.2.0`.
- Standalone Redis cache mode can still run through the older native ABI fallback, but Sentinel and
  Cluster mode require the newer ABI so topology routing is explicit and fails early if the wrong
  native binary is loaded.
- The packaged Linux native library is built on a manylinux2014/glibc 2.17 baseline and verified with
  maximum required GLIBC symbol `GLIBC_2.14`. This avoids the previous risk of shipping a native
  binary that works on a new build image but fails on older CentOS/UBI based production images.

## How To Use It

Use these versions together when the application combines REST and the Redis cache library:

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>3.2.3</version>
</dependency>

<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>java-rust-cache</artifactId>
  <version>0.2.0</version>
</dependency>
```

For small REST services, keep starting with `micro-rest`. Enable Redis cache topology separately in
the cache library configuration. Do not increase global worker or queue settings just because Redis
is enabled; keep Redis read/write connection pools and inflight limits bounded.

## Validation

The release was validated with:

- Rust native unit tests.
- Maven test/install for `rust-java-rest`.
- Maven test/install for `java-rust-cache`.
- Sample cache reader and writer package builds.
- Standalone Redis integration gate.
- Redis Sentinel failover gate.
- Redis Cluster `MOVED`/`ASK` redirect gate.
- Redis Cluster replica failover gate.
- Linux native GLIBC symbol check for the packaged `.so`.

This release is stable for the tested REST/cache integration paths. For a new production workload,
still run the endpoint matrix and idle/soak memory proof under your real Kubernetes CPU and memory
limits before treating benchmark numbers as capacity.
