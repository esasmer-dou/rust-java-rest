# Rust-Java REST 4.0.0

`4.0.0` makes the normal application path more declarative while keeping business logic in Java and
HTTP I/O in Rust Hyper.

## What Users Get

- Build-time generation for component, route, and property indexes.
- Generated direct JSON writers and JDBC record mappers for selected records.
- A separate `codegen` JAR that is used by Maven only during compilation and is not added to the
  production runtime classpath.
- Explicit runtime profile plans and reusable health/readiness components.
- Compile-verified examples for CRUD, upload, streaming, WebSocket, and benchmark-oriented routes.
- Safe default package generation when an artifact ID contains a Java keyword such as `static`.
- English and Turkish configuration, operations, troubleshooting, and declarative development guides.

## Dependency

```xml
<dependency>
  <groupId>com.reactor</groupId>
  <artifactId>rust-java-rest</artifactId>
  <version>4.0.0</version>
</dependency>
```

Use the code generator only in `maven-compiler-plugin`:

```xml
<annotationProcessorPaths>
  <path>
    <groupId>com.reactor</groupId>
    <artifactId>rust-java-rest</artifactId>
    <version>4.0.0</version>
    <classifier>codegen</classifier>
  </path>
</annotationProcessorPaths>
```

## Migration From 3.x

| Removed API | Replacement |
|-------------|-------------|
| `FastMapV2` | `RequestValueMap` or typed/direct parameter binding |
| manual `StartupIndexGenerator` | `ReactorStartupProcessor` from the `codegen` classifier |
| `RestApplication.sleepForever()` | `RestApplication.run(...)`, `start(...)`, or `startAsync(...)` |
| duplicate allocation-based primitive parsers | typed/direct path and query binding |

Handlers, services, records, REST annotations, validation, and database code remain Java code. The
native binaries and ABI values are unchanged in this release: REST `24`, Dubbo `7`, Redis `6`.

## Aligned Companion Versions

- `java-rust-cache:0.5.0`
- `java-rust-dubbo:0.5.0`
- `rust-sample-model:0.3.0`
- `rest-sample-utility:0.3.0`

Do not copy a DLL or SO from an unrelated release. Startup provenance checks fail early when the
packaged native runtime is incompatible.
